# JARVIS → Telegram: одноразовая настройка

В репозитории уже создан workflow: `.github/workflows/jarvis-telegram.yml`.
Он отправляет **публичные, обезличенные** отчёты JARVIS в личное сообщение Telegram после появления файлов `jarvis/reports/weekly-YYYY-MM-DD.md` или `jarvis/reports/approval-YYYY-MM-DD.md` в ветке `main`.

## 1. Создайте Telegram-бота

1. В Telegram откройте официальный [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot`, задайте название, например «JARVIS Reports», и свободное имя, заканчивающееся на `bot`.
3. BotFather выдаст API-токен. **Не отправляйте его в ChatGPT, публичные документы, GitHub-файлы или сообщения друзьям**.
4. Перейдите в созданный бот и нажмите **Start** (`/start`), иначе бот не сможет написать вам первым.

## 2. Узнайте свой числовой Chat ID

Для личных сообщений боту нужен числовой Telegram Chat ID. Получите его из Telegram Bot API через `getUpdates` после `/start` (не публикуйте токен) либо через отдельный бот, показывающий Telegram user ID, если доверяете такому сервису. В приватной беседе `message.chat.id` из результата `getUpdates` обычно совпадает с ID Telegram-пользователя. Это не номер телефона и не username.

Пример локально на компьютере (вводить токен только в локальную командную строку, не в чат, не в файл репозитория):

```bash
read -rs -p "Telegram Bot Token: " BOT_TOKEN; echo
curl -fsS "https://api.telegram.org/bot${BOT_TOKEN}/getUpdates"
unset BOT_TOKEN
```

Найдите поле `message.chat.id` после своего `/start`. Если пусто — ещё раз напишите своему боту `/start` или текстовое сообщение и повторите.

## 3. Добавьте секреты в GitHub

Зайдите в [Settings → Secrets and variables → Actions](https://github.com/Koda1234567/Koda1234567/settings/secrets/actions) и по очереди создайте **Repository secret**:

- `JARVIS_TELEGRAM_BOT_TOKEN` — полный токен от BotFather.
- `JARVIS_TELEGRAM_CHAT_ID` — числовой `message.chat.id`.

Важно: токен никогда не хранить как GitHub **Variable** или в обычном файле. Убедитесь, что доступ к репозиторию защищён двухфакторной аутентификацией, поскольку его владельцы могут менять Actions и использовать эти секреты.

## 4. Проверка

Откройте [Actions → JARVIS reports to Telegram](https://github.com/Koda1234567/Koda1234567/actions/workflows/jarvis-telegram.yml), нажмите **Run workflow**. Запуск `workflow_dispatch` отправит одно тестовое сообщение «✅ JARVIS — тест Telegram-подключения» в выбранный чат.

Не нажимайте повторно много раз: каждое ручное выполнение отправляет новый тест.

Если секретов нет, ручной тест завершится ошибкой с инструкцией; автоматические отправки тихо пропускаются до настройки.

## Откуда берутся отчёты

JARVIS-координатор по пятницам по своему расписанию анализирует результаты и должен создать **сначала** полный отчёт в Space JARVIS, а **затем** краткий безопасный для публикации файл `jarvis/reports/weekly-YYYY-MM-DD.md` через GitHub. Коммит нового файла в `main` автоматически запускает Telegram workflow. Отдельный срочный пакет может быть отправлен через `jarvis/reports/approval-YYYY-MM-DD.md` при наличии согласованного и проверенного содержания.

**Важные ограничения**:
- Бот пересылает **только** отчёты, действительно сохранённые в GitHub в указанные пути. Сам ChatGPT не имеет прямого Telegram-коннектора; выполнение расписания и доступ к GitHub нужно проверить по результатам первого запуска.
- Репозиторий **публичный**. Не публикуйте персональные данные заказчиков, личные телефоны, переписки, конфиденциальные договоры, API-токены и коммерческие секреты. Для таких материалов используйте частное Space или хранилище. Telegram получает лишь обезличенную сводку со ссылками.
- После удаления секретов отправка перестаёт работать. Токен всегда можно отозвать через @BotFather.
