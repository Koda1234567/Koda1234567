# Первый реальный звонок Новофон → Звонко

## Подготовленный установочный пакет (19 ноября 2026)

Для **нового** Ubuntu 24.04 VPS в РФ:

```bash
git clone https://github.com/Koda1234567/Koda1234567.git
cd Koda1234567/zvonko/telephony
sudo bash install-ubuntu.sh
```

Установка создаёт сервис и Python-окружение, но не подключает SIP, не запускает AI и не звонит.

Дальше **только после создания отдельного SIP-логина для робота**:

```bash
sudo bash configure-novofon.sh
sudo bash check-server.sh
```

Пароль SIP вводится в терминале сервера с маскировкой. Скрипт откажется применять существующий логин софтфона `0157329`. Затем нужно установить Ollama, загрузить `qwen2.5:7b`, Faster Whisper и Vosk TTS, после чего включить `sudo systemctl enable --now zvonko`.

Нет подключённого российского VPS, поэтому **живой SIP-вызов с ИИ ещё не сделан**. Самостоятельный эхо-тест Новофона подтверждает лишь связь оператора. На CPU голосовой диалог может работать медленно; задержку оценить только после живого разговора.

## Безопасный тест без звонков на мобильный

1. В кабинете Новофона создайте **отдельную SIP-учётную запись/сотрудника** для робота, например с внутренним номером 101. Важно: это не просто внутренний номер без учётных данных — нужно получить собственные SIP-логин/пароль, которые будет регистрировать Asterisk. Существующий номер 100 оставить в софтфоне.
2. На VPS Ubuntu установить Asterisk с res_pjsip, res_ari, res_stasis, res_rtp_asterisk и установить Python-зависимости из `requirements.txt`.
3. Создать на VPS приватный `/etc/asterisk/pjsip.conf` по шаблону `asterisk/pjsip.conf.example`. Заполнить REPLACE_SIP_LOGIN и REPLACE_SIP_PASSWORD **только на сервере**, не в GitHub и не в чате. Применить файлы `asterisk/http.conf`, `asterisk/ari.conf`, `asterisk/extensions.conf`. Сгенерировать отдельный секрет ARI и заполнить `ARI_PASSWORD` сервиса.
4. Проверить регистрацию из терминала сервера:

   ```sh
   sudo asterisk -rx "pjsip show registrations"
   sudo asterisk -rx "pjsip show endpoints"
   sudo asterisk -rx "module show like res_ari"
   ```

   Должна быть регистрация **Registered**. Если она не зарегистрирована, звонить не пробовать.
5. На сервере установить Ollama с Qwen 2.5 7B, Faster Whisper и Vosk TTS, настроить `.env` (пример `.env.example`), загрузить модели, запустить `python server.py`. Проверить локально `curl -s http://127.0.0.1:8766/health`. До ответа `asterisk: true` не пробовать звонить.
6. Из существующего софтфона с внутреннего номера 100 **вручную набрать 101**. Если провайдер маршрутизирует этот внутренний вызов на новую SIP-учётную запись 101, Asterisk примет звонок, отправит аудио в голосовой движок и ответит как ИИ. **Это необходимо проверить, а не предполагать.**
7. Зафиксировать реальный результат: дошёл ли вызов до Asterisk, слышно ли голос, распознал ли речь, сколько секунд задержка, можно ли перебить. Улучшать качество после измерения.

## Возможные проблемы

- Если Novofon не передаёт звонки между сотрудниками АТС на отдельный зарегистрированный SIP-клиент, проверить маршрутизацию в настройках ВАТС.
- Одновременно использовать один и тот же SIP-логин в софтфоне и на сервере ненадёжно. Поэтому выделить роботу отдельную линию.
- SIP 5060/UDP и диапазон RTP 10000–20000/UDP должны быть доступны **только в соответствии с политикой оператора**, без открытого анонимного транка. ARI и `/health` держать исключительно на localhost, пароли в приватных файлах.
- Входящий тест не требует рекламного автодозвона. Не загружать персональные данные клиентов в Cloudflare.
- На CPU с Qwen 7B и Whisper small реплики могут идти **несколько секунд**, качество и задержки заранее не гарантированы.
- Для постоянного естественного голоса имеет смысл выделенный российский TTS/STT сервис или GPU; выбор после первого реального SIP-теста.

Источники: [официальная инструкция Novofon Asterisk PJSIP](https://novofon.com/instructions/calls/asterisk-pjsip/), [Asterisk External Media](https://docs.asterisk.org/Development/Reference-Information/Asterisk-Framework-and-API-Examples/External-Media-and-ARI/).
