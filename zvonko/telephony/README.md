# Звонко — настоящий телефонный ИИ (SIP/RTP, РФ)

Это **сервер настоящих звонков**, а не голосовой чат. Asterisk (на сервере в РФ) подключается к SIP-транку заказчика; модуль `server.py` принимает/отправляет G.711 RTP, использует VAD, faster-whisper, локальный Ollama и Vosk TTS (5 русских голосов). Перебивание робота предусмотрено. Разговоры и контакты не отправляются в Cloudflare.

**Что проверено:** локальные unit-тесты кодеков RTP/PCMU и API безопасности; полноценного SIP-звонка на реальный номер пока не было, так как нет настроенного SIP-транка и Asterisk. Качество голоса и задержки на реальном звонке ещё требуют проверки. Не выдавать прототип за действующий массовый сервис.

## Как запустить на своём сервере в РФ

1. Установить Asterisk 20/22+, включить ARI, res_stasis, externalMedia; создать SIP-транк у оператора (МТС Exolve / Zadarma / другой, если разрешает внешний SIP/RTP). Договор и минуты оплачивает клиент оператору напрямую.
2. Использовать файлы `asterisk/http.conf`, `asterisk/ari.conf`, `asterisk/extensions.conf`; `pjsip.conf.example` — только шаблон. Реальные настройки и секреты взять из кабинета своего SIP-оператора. ARI держать только на localhost.
3. Установить Python 3.11 и зависимости `pip install -r requirements.txt`. Установить [Ollama](https://ollama.com/download), загрузить `ollama pull qwen2.5:7b`.
4. Установить [Vosk TTS](https://github.com/alphacep/vosk-tts) и голосовой пакет `vosk-model-tts-ru-0.9-multi` из официальных моделей. Для другого голоса `TTS_SPEAKER=0…4`.
5. Заполнить `.env` из `.env.example`. Обязательно задать `ARI_PASSWORD` и случайный `ADMIN_TOKEN` от 24 символов; не загружать их на GitHub. Экспортировать переменные и запустить `python server.py` как закрытый systemd сервис.
6. Настроить входящий номер на `Stasis(zvonko,inbound)`. Позвонить на него с собственного телефона, проверить RTP в обе стороны, речь, отключение, задержки, работу при обрыве.

### Один тестовый исходящий звонок

Когда Asterisk уже работает, задать `TEST_NUMBERS=+7XXXXXXXXXX` (свой номер), `CALLER_ID` разрешённый оператором, `ENABLE_TEST_OUTBOUND=true`. Запускать вручную **только** локальным защищённым запросом:

```bash
curl -X POST http://127.0.0.1:8766/manual-test \
  -H 'Authorization: Bearer <ADMIN_TOKEN>' \
  -H 'Content-Type: application/json' \
  --data '{"number":"+79991234567"}'
```

Сервис запрещает другие номера, одновременные звонки и повторную попытку чаще 90 секунд. Ответ API `accepted` — это команда на исходящий звонок, а не подтверждение соединения. Массового автодозвона нет.

### Важно для РФ

Статья 18 38-ФЗ запрещает автоматический набор номеров без участия человека **для распространения рекламы**, даже при наличии предварительного согласия. Приоритет для продукта: реальные входящие звонки, запрошенные клиентом соединения и ограниченные технические испытания. Коммерческие исходящие сценарии, маркетинг, маркировку, согласия и обработку персональных данных проверять с юристом и оператором. Реальные персональные данные граждан РФ хранить/обрабатывать с учётом локализации и 152-ФЗ.

Источники: [38-ФЗ, ст.18](https://www.consultant.ru/document/cons_doc_LAW_58968/f892dec1383709792452f18d36e7043306e2be0a/), [Asterisk External Media/ARI](https://docs.asterisk.org/Development/Reference-Information/Asterisk-Framework-and-API-Examples/External-Media-and-ARI/), [Звонки через SIP Exolve](https://exolve.ru/products/sip-trunk/), [Zadarma SIP trunk](https://zadarma.com/ru/services/calls/sip-trunk/).

### До коммерческого запуска ещё нужно

Обкатать SIP у оператора, измерить задержки STT/LLM/TTS и улучшить потоковое воспроизведение, проверить лицензию всех моделей и безопасность, настроить многоарендность, роли, серверную CRM и обработку персональных данных **в России**. Никаких заранее заявленных продаж и успешных звонков.
