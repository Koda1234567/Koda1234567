# «Звонко 2.0» — локальный голосовой B2B-тест

Поддерживаемая схема: MicroSIP (Windows) → Asterisk (Ubuntu WSL2 mirrored) → ARI → Whisper STT → Ollama Qwen → Piper TTS (русский). Для этого теста Новофон и внешний телефонный номер не нужны.

## Переход с Vosk на Piper

В окне, где работает `bash start-local-ai-wsl.sh`, нажать Ctrl+C, затем:

```bash
cd ~/Koda1234567/zvonko/telephony
git pull
bash install-piper-wsl.sh
bash start-local-ai-wsl.sh
```

Если загрузка голосовой модели не открывается напрямую, включить XRay и запустить установку через его локальный HTTP-прокси:

```bash
ZVONKO_DOWNLOAD_PROXY=http://127.0.0.1:10801 bash install-piper-wsl.sh
```

Установщик проверяет, что русская модель действительно синтезирует голос, прежде чем переключить `~/.config/zvonko/ai.env`. Файл с SIP-паролем и ARI-паролями не выводится. Asterisk не перенастраивается.

## Тест

Дождаться `Connected to local Asterisk ARI`, из MicroSIP позвонить на **200** и проверить:

- Реакцию на «Привет, вы меня слышите?» (быстрый отклик).
- Вопрос о конкретной задаче уборки и площади.
- Возражение «У нас уже клининговая компания».
- Вопрос о цене без указанной модели (не выдумывает цифры).
- «Мне неинтересно» (вежливо прекращает разговор).

В журнале обращать внимание на `STT`, `AI reply ready` и `Reply played: first audio`. Это независимые замеры, а не обещанные показатели.

## Сценарий B2B

Рабочая конфигурация хранится в `~/.config/zvonko/ai.env`: `SALES_OFFER`, `SALES_GOAL`, `PRODUCT_INFO`. Не хранить в GitHub данные клиентов и пароли. Отказы клиента обязательны, ручное исходящее тестирование только с его согласия. Ни отправки КП, ни записи лида в CRM, ни вызова менеджера пока нет; нельзя утверждать обратное.

## Возврат к прежнему голосу

Остановить процесс Ctrl+C. В конфигурации `~/.config/zvonko/ai.env` заменить `export TTS_ENGINE=piper` на `export TTS_ENGINE=vosk`, затем `bash start-local-ai-wsl.sh`. Изменения SIP-конфигурации для отката не нужны.
